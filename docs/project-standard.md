# Общий стандарт Ёж MCP

## Устройство репозитория

- README: задача пользователя, статус, платформы, быстрый старт и ограничения.
- AGENTS: установка и сопровождение другим агентом без раскрытия секретов.
- docs: один актуальный старт, права, диагностика, обновление и откат. Старые отчёты отдельно, не выдаются за текущую инструкцию.
- examples и tests: только искусственные данные.
- CONTRIBUTING, SECURITY и формы Issues/PR: вход для сообщества.
- Лицензия, закреплённые зависимости и проверяемый источник upstream.

Не складывайте в исходники .venv, node_modules, токены, сессии, браузерные профили, переписки и выгрузки клиента. У установленного экземпляра и публичного исходного пакета разные каталоги состояния. Обновление не заменяет существующую авторизацию и права молча.

## Проверки и статусы

Различайте: исходники проверены офлайн; MCP initialize/list_tools прошли; владелец вошёл; нужная операция реально выполнена; результат прочитан обратно в конечном клиенте. Аннотация readOnlyHint сама по себе не является защитой: ограничения проверяются сервером.

Начальный профиль — чтение, явно объяснённое владельцу. Запись, отправка, удаление, вступление, расписания и администрирование включаются отдельно по поручению. Существующие выбранные права сохраняются. Неопределённую отправку сначала сверяют по прежней квитанции; новый request_id для слепого повтора не создают.

Удобное имя продукта не требует переименования действующего пути, технического ID или репозитория. В текущей линейке используются Ёж Codex MCP, Ёж Computer MCP, Ёж Telegram MCP, Ёж ToDo MCP и Ёж Agent Inbox MCP; старые адреса сохраняют совместимость.
