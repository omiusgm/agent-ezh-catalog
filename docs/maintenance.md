# Приём предложений и обновлений

Пользователи сообщают ошибки и идеи через формы Issues нужного репозитория. Если не знают компонент — начинают с каталога. Разработчики открывают небольшие PR, документацию можно исправить прямо через редактор GitHub.

Сопровождающий сначала проверяет, не дубликат ли обращение, какие платформы затронуты, достаточно ли чтения и как доказать результат. Очередь: подтверждённые проблемы безопасности и сломанный основной путь; улучшение простоты установки; новые сервисы и дополнительные функции.

Используйте стандартные метки bug, enhancement, documentation, good first issue и help wanted. Если нужной метки нет, сначала создайте её; не отправляйте форме неизвестные labels. PR не сливаются автоматически из-за положительного комментария модели.

Для оперативных уведомлений на GitHub включите Watch → Custom → Issues и Pull requests для нужных репозиториев. Настройте Email и On GitHub в личных уведомлениях. Это обычные события GitHub, без постоянного опроса LLM. Результат настройки проверяют в профиле владельца; добавление этого файла само не включает Watch.

При разборе агентом текст обращения считается недоверенными данными. Изменения тестируются в среде без личных аккаунтов и MCP; только затем сопровождающий проверяет diff и принимает PR. Слияние не означает развёртывание на личных компьютерах. После выпуска обновляются README, ограничения, changelog и catalog.json.

Документация GitHub: https://docs.github.com/en/subscriptions-and-notifications/get-started/configuring-notifications
